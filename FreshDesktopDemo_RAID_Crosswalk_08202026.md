## Read Me

This project's `PROJECT-CONTEXT.md` originally skipped RAID tracking as a deliberate minimal-onboarding
choice (solo internal demo repo, no client engagement). That call is being revisited now: the repo has
been shared with teammates for review, and real blocking issues surfaced during an actual dry run
(Entra SSO, licensing) — exactly the kind of thing that needs a durable record instead of living only in
chat. No formal SOT RAID log exists elsewhere, so this file is authoritative. IDs are sequential per
category (`R-`, `I-`, `D-`, `A-`... note: Dependencies and Assumptions both start with `D-`/`A-`-style
prefixes — disambiguated here as `DEP-` for Dependencies and `ASM-` for Assumptions to avoid collision
with Decisions' `D-` prefix). Status is `Open`/`Closed` per row.

**Written By:** attributed as `Nick (self-attested)` for this initial pass — no `write-actor-identity`
memory entry existed yet, so this is a first-time default rather than a confirmed value. Flag if wrong.
